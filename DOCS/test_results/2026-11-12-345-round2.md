# #345 round 2: distractors, adapter, and the `/api/embed` omission

**Scope:** 10 generations, owner-authorized on 2026-11-12, sent directly to
the production Ollama (GTX 1080 Ti, 11 GB). No production configuration
changed and nothing was re-ingested. All arms used `num_ctx` 16,384, seeds
{11, 23}, the Step 0 question and system prompt, and model digest
`359d7dd4…`. Arms vary only the evidence or the adapter. This is n = 2 per
cell, so it is directional only.

[`DOCS/evaluations/inference-pilot-345/`](/DOCS/evaluations/inference-pilot-345/)
and pinned to LF line endings. They are built reproducibly by
`scripts/inference_pilot_345.py` (`build-context`, `build-mixed`).

**Exact provider requests.** `generate` arms use the LiteLLM `ollama/` body:
`/api/generate` with a flattened `### System:` / `### User:` prompt. `chat`
arms use the LiteLLM `ollama_chat/` body: `/api/chat` with system and user
roles and `images: []`. With production's empty `options`, both builders

`{"num_ctx", "seed"}`: equivalent JSON, different bytes. The fidelity gate also
reproduced the Step 0 wire body exactly. Every arm's full request body,
response, `thinking` and `/api/ps` reading is in the raw records
(`_raw/2026-11-12-345-round2/`, indexed with sha256 in `raw-index.json`).
`options` is `{num_ctx, seed}` throughout. Sampling comes from the
Modelfile (temperature 0.6, top_k 20, top_p 0.95), as in production.

**Grading rubric** (manual, against the reviewed sequence in the
[answer key](/DOCS/evaluations/inference-pilot-345/impl-trace-answer-key.json)):

- **Correct:** the entry point, `run_rag`, `hybrid_retrieve` and the
  `/v1/vectors/search` HTTP call are named in the right order. The vector
  search is classified as HTTP, and no component is invented.
- **Partial:** the main path is right but contains an ordering or
  classification error, or it explicitly attributes a function to the
  wrong source file. Listing a function under the file that calls it is
  not counted as an error when its definition is absent from the evidence.

No answer named a file or function absent from the evidence. Two answers
expanded HNSW (which is in the evidence) incorrectly, as "Hierarchical
Navigable Wavelet" or "Navigational Search". This is a world-knowledge
error, not invented evidence.

## Findings

**1. Distracting documentation did not stop the trace.** In 4/4 mixed runs
the model built the trace from the implementation and ignored the historical
documentation. It neither repeated the documentation's claims nor declined
to answer. Two runs were correct and two partial, compared with 2/2 correct
for clean `implementation` with `generate` in this round. Order (docs first
versus implementation first) showed no clear effect at n = 2. Mixed prompts
cost about 1,000 extra prompt tokens and under 5 s of prompt evaluation.

**2. The adapter made no demonstrable difference.** `chat` gave one correct
and one partial; `generate` gave two correct. Both share the same error
types. At n = 2 that is not a meaningful difference. There is no evidence
here that the flattened `ollama/` prompt harms this question, and none that
`ollama_chat/` helps.

**3. The `/api/embed` omission is not caused by missing evidence.**

- **Witness presence:** in every evidence variant, the context contains
  `requests.post(f"{self.base_url}/api/embed", …)` inside
  `OllamaEmbedder.embed`, and `run_rag` carries the comment
  `embed_query -> OllamaEmbedder.embed makes a synchronous requests.post`.
- **Witness explicitness:** one link was implicit in round 1. Which embedder
  `run_rag` gets is decided by `get_embedder(provider=settings.EMBEDDING_PROVIDER, …)`,
  and that factory was not in the context. The `implementation_factory`
  variant closes that gap.
- **Outcome:**

  | Round | Ollama HTTP identified |
  |---|---|
  | Round 1 | 0/4 |
  | Round 2, all arms | 6/10, at least partly |
  | Round 2, factory variant | 1/2, partly |

  Adding the factory did not make it reliable. Across round 2, the literal
  `/api/embed` appears in the reasoning trace in 6/10 runs, but in only
  2/10 answers (the others say "Ollama API").
- **Classification:** the evidence was present, and with the factory it is
  complete. The omission is **inconsistent salience and judgment, not an
  evidence gap**. The model often treats embedding as an in-process step,
  and the Ollama server as not one of "the services" the question means.
  This is a reasoning failure only in the weak sense of inconsistent
  inclusion; the question does not explicitly ask about model-provider
  calls. It is not evidence that the model cannot read the witness.

**4. Seeded runs are not reproducible across sessions, and arm order is a
confound.** The two `implementation` / `generate` / 16K arms sent
byte-identical requests to round 1's arms, yet produced 5,712 and 3,358
completion tokens against round 1's 4,279 and 2,702. The answers also
differ. The likely cause is the **prompt-cache state**:

- In round 1, the 8K and 16K arms gave byte-identical output, with seed 11
  cold after a model reload and seed 23 cached in both.
- In this round, seed 11 hit a cache warmed by the preceding arm with a
  shared prefix.

This is consistent with cache reuse changing numerics, but it is not
proven. Consequences:

- Two seeds sample variability, but a seed alone does not reproduce a run.
- Arms that differ in cache state are not strictly comparable.
- Round 1's lost raw records cannot be regenerated exactly.
- Future runs should control the cache, for example by unloading between
  arms (`keep_alive: 0`, at a cost of about 7 s of reload per arm), and
  record it.

This is also relevant to #349 as an observed source of context sensitivity.

**5. Cost at 16K.** VRAM is a constant 4.75 GiB. Prompt evaluation is at
most 4.7 s for 5k-token prompts. Latency of 49-112 s is driven by
completion length (2.7k-6.5k tokens, mostly reasoning at about 60 tokens
per second), not by evidence size.

## What this does not show

- n = 2 per cell, one question. The rates are not estimates.
- The distractors were the real Step 0 documentation, but there was only
  about 4 KB of it, against 17 KB of implementation. A realistic retrieval
  mix, with more distractor volume and partial implementation, is
  untested.
- The cache confound means the per-arm differences in this table should not
  be read as treatment effects.

## Suggested next steps (not authorized; for discussion)

1. Before any larger matrix, make runs cache-controlled (unload between arms)
   and record cache state, then repeat a small determinism check. No other
   change.
2. A realistic-evidence arm: the orchestrator's actual candidate set at a 16
   or 32 KB budget (the protocol's Set B). This links #345 to #194 and #342.
3. Keep the adapter question open, but deprioritize it: nothing here argues
   for changing `ollama/`.

No production tuning is proposed from these results.
