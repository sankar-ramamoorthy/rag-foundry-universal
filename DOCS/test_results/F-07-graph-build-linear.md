## Fixture generation parameters

Synthetic repos generated by [`graph_baseline.py`](graph_baseline.py)
(committed alongside this document). Per file: 30 module-level functions
(3 lines each, each calling the next — a call chain), plus one class with
5 methods calling those functions, plus one import statement.

| Config | Files | Entities produced | Relationships produced |
|---|---|---|---|
| N=40 | 40 | 2,720 | 2,640 |
| N=80 | 80 | 5,440 | 5,280 |

A separate small fixture repo exercised correctness edge cases: decorated
functions, nested classes, indented methods, unicode text, form feeds
(`\f`) inside source, CRLF and CR-only line endings, single-line defs,
files without trailing newline, and a Markdown file.

## Command

From `ingestion_service/`, using the repo-root venv:

`ingestion_service/tests/codebase/test_graph_build_linear.py` and run with:

```
cd ingestion_service && ../.venv/Scripts/python.exe -m pytest tests/codebase/ -q
```

## Results

| Config | Entities | Before (s) | After (s) | Speedup |
|---|---|---|---|---|
| N=40 | 2,720 | 2.169 | 0.213 | ~10.2× |
| N=80 | 5,440 | 5.151 | 0.380 | ~13.6× |

Scaling behavior: doubling the repo grew build time **2.37×** before
(superlinear — quadratic terms dominated by `_canonical_from_id` /
`_resolve_in_scope` full-entity scans and per-artifact `ast.parse`) and
**1.78×** after (linear). The gap widens with repo size; at
audit-projected scale (50k artifacts) the before-code was effectively
un-ingestable.

## Byte-identical verification method (ADR-030)

1. **Before** the refactor, the harness built the graph over the
   edge-case fixture repo with a *fixed* `ingestion_id` and dumped every
   entity (`canonical_id`, `artifact_type`, `name`, `parent_id`, `id`,
   full extracted `text`, `doc_type`, `title`) plus all relationships,
   sorted, to JSON (`before.json`, `before80.json`).
2. **After** the refactor, the identical harness produced `after.json` /
   `after80.json`.
3. A structural equality check (`json.loads(...) == json.loads(...)`,
   stats excluded) confirmed both pairs identical — **entities,
   relationship sets, and every artifact's extracted text byte-for-byte**.

The risky part was text extraction: the old path called
`ast.get_source_segment` per artifact; the new path slices pre-split
lines. `ast.get_source_segment` has two subtle behaviors the replica must
match — column offsets are **UTF-8 byte offsets** into the encoded line,
and lines split only on `\n`/`\r`/`\r\n` (never form feed or other
unicode breaks). Both are pinned by parametrized tests comparing
`_source_segment` output against `ast.get_source_segment` on the
edge-case sources, plus a lossless-split test
(`"".join(lines) == source`).

Additional guards in `test_graph_build_linear.py`:

- parse-count test (monkeypatched `ast.parse`): a file with ~35 artifacts
  must be parsed ≤ 2 times (extractor pass + text-index pass) — fails if
  per-artifact re-parsing regresses;
- rebuild determinism: same repo + same `ingestion_id` → identical
  entity order, texts, and relationships;
- `entities_by_id` index consistency: every indexed entity is the same
  object a linear scan over `entities` would find.
